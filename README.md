# Кинотеатр «Аврора»

Веб-приложение афиши кинотеатра и бронирования билетов: публичная афиша с фильтрами и поиском, карта зала с выбором мест, оформление заказа и панель администратора (фильмы, сеансы, заказы). Учебный проект (лабораторные работы, вариант 6).

## Стек

| Часть    | Технологии                                                                 |
| -------- | -------------------------------------------------------------------------- |
| Клиент   | React 18, Vite 6, TypeScript, react-router, axios                           |
| Сервер   | Node.js (≥ 20.12), Express 4, TypeScript, tsx, zod, JWT, bcryptjs           |
| БД       | PostgreSQL 15 (Docker), Prisma 6                                            |
| Качество | ESLint (flat config) + typescript-eslint, Prettier, `tsc --noEmit`          |
| Docs     | Swagger UI: `http://localhost:4000/api/docs`                                |

## Требования

- Node.js **20.12+** (используется `process.loadEnvFile` для загрузки `.env`)
- Docker (для PostgreSQL или для всего стека одной командой)

## Быстрый старт

### Вариант 1: всё в Docker одной командой

```bash
docker compose up --build
```

Поднимутся PostgreSQL, API и клиент. Сайт: http://localhost:5173, API: http://localhost:4000/api (документация — `/api/docs`). При первом запуске БД автоматически наполняется демо-данными. Данные сохраняются в томе `cinema_pgdata` между перезапусками.

### Вариант 2: локальная разработка (Node.js)

```bash
# 1. Поднять только PostgreSQL (порт 5433, БД/пользователь/пароль: cinema)
docker compose up -d db

# 2. Сервер
cd server
npm install
cp .env.example .env        # Windows: copy .env.example .env
# ОБЯЗАТЕЛЬНО задайте JWT_SECRET в .env — без него сервер не запустится.
# Сгенерировать секрет: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
npm run db:setup            # prisma generate + db push + страховочный индекс мест
npm run dev                 # API на http://localhost:4000

# 3. Клиент (в отдельном терминале)
cd client
npm install
npm run dev                 # http://localhost:5173 (прокси /api -> :4000)
```

При первом запуске сервер автоматически наполняет БД демо-данными (залы, фильмы, сеансы на неделю, примеры заказов) и создаёт администратора.

**Демо-доступ в панель:** логин `admin`, пароль `admin123` (только для разработки).

## Переменные окружения (`server/.env`)

| Переменная     | Назначение                                                        |
| -------------- | ----------------------------------------------------------------- |
| `DATABASE_URL` | строка подключения к PostgreSQL (см. `.env.example`)              |
| `JWT_SECRET`   | секрет подписи JWT — **обязателен**, без него сервер падает сразу |
| `PORT`         | порт API (по умолчанию 4000)                                      |
| `DEMO_MODE`    | `0` — отключить генерацию демо-заказов автофиллом (по умолчанию включена) |
| `ADMIN_LOGIN`  | логин администратора для первого сида (по умолчанию `admin`)        |
| `ADMIN_PASSWORD` | пароль администратора для первого сида; дефолт `admin123` — только в демо-режиме, при `DEMO_MODE=0` **обязателен** |

Файл `.env` не попадает в git (см. `.gitignore`); шаблон — `server/.env.example`.

## Особенности реализации

- **Целостность бронирования:** продажа мест сериализуется транзакцией с блокировкой строки сеанса (`SELECT … FOR UPDATE`), а в БД дополнительно стоит partial unique index `uq_order_items_active_seat` — двойная продажа одного места невозможна даже при гонке (409).
- **Расписание:** сервер следит, чтобы на ближайшие дни всегда были сеансы (автозаполнение при старте и раз в час, приоритет — реже показываемые фильмы). Заполнение идёт в одной транзакции под advisory-блокировкой — параллельные запуски не создают дублей.
- **Демо-данные под контролем:** заказы генератора витрины помечены `isDemo` (значок «демо» в панели), не учитываются в статистике и отключаются переменной `DEMO_MODE=0`. Сид восстанавливает только недостающее (админ, залы, каталог) — частичное удаление данных не ломает старт.
- **Защита входа:** не более 10 попыток `/api/auth/login` с одного IP за 15 минут (429 + `Retry-After`).
- **Админ-ограничения:** нельзя менять зал/фильм сеанса с проданными билетами, реактивация отменённого заказа проверяет занятость мест, удаление фильмов/сеансов с заказами запрещено.
- **Swagger:** полная документация API — `http://localhost:4000/api/docs`.
